# 7. Project Demonstration

## Preparation
Configure the environment, run the application and ensure Gemini model access. Use synthetic profiles for demonstrations. Do not expose `.env`, API keys, admin passwords or real private plan links in screenshots or recordings.

## Demonstration script
1. Introduce the problem and the four project scenarios.
2. Show the modular code structure and architecture/schema diagrams.
3. Open the form. Use a fictional profile: Alex, 24 years, 65 kg, muscle gain, medium intensity, beginner, dumbbells, 30-minute sessions.
4. Generate a workout. Show its seven days and nutrition tip. Explain that it is saved.
5. Submit “Add another recovery day and more cardio.” Show the revised version and expand the original to prove it remains available.
6. Open Nutrition tip, select weight loss and request an independent tip.
7. Authenticate to Coach dashboard without recording credentials. Show profile details, original/revised plans and feedback.
8. Restart the local app and revisit the private plan to demonstrate persistence.
9. Show API documentation and automated tests. Explain that health checks do not test Gemini access.
10. Explain hosted persistence requirements and the AI guidance limitations.

## Evidence checklist
- Home, generated plan, feedback/history, tip and coach screenshots.
- Recording URL, created by the submitter after running the live demo.
- Test output and actual model/configuration used.
- Local restart proof or persistent hosted storage proof.
- Team/institution details, if required.

These items are a script/checklist, not a claim that a live demonstration or recording has already been completed.
